## Partial de-duplication in report service

`buildStudentSummary` centralizes the status-counting and percentage logic for `getClassReport` (unfiltered) and `getClassReportFiltered` (level-scoped), accepting a nullable `scopeSurahQuery` parameter that controls whether progress is fetched globally or scoped to a level's surahs.

`getLevelReport` at lines 120-145 still contains its own copy of the same logic:

```javascript
const progress = db.prepare(`
  SELECT p.status, COUNT(*) as count
  FROM progress p
  INNER JOIN level_surahs ls ON p.surah_id = ls.surah_id
  WHERE p.student_id = ? AND ls.level_id = ?
  GROUP BY p.status
`).all(student.id, levelId);

const statusCounts = { NOT_STARTED: 0, ... };
let tracked = 0;
progress.forEach(p => { statusCounts[p.status] = p.count; tracked += p.count; });
statusCounts.NOT_STARTED = totalSurahs - tracked;
const memorizedTotal = statusCounts.MEMORIZED + statusCounts.PERFECT;
const progressPercentage = totalSurahs > 0 ? Math.round(...) : 0;
```

This is functionally identical to what `buildStudentSummary` does when passed the level-scoped query. The fix is a one-line replacement:

```javascript
const summary = buildStudentSummary(db, student.id, scopeQuery, [levelId], totalSurahs);
```

This is a maintenance hazard if someone later changes how statuses are counted and only updates the helper.
